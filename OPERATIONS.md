# Operations Guide — Public Deployment

## TLS

Never expose Node directly. Terminate TLS at a reverse proxy.

```nginx
server {
  listen 443 ssl http2;
  server_name water.example.org;

  ssl_certificate     /etc/letsencrypt/live/water.example.org/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/water.example.org/privkey.pem;
  ssl_protocols TLSv1.2 TLSv1.3;

  add_header Strict-Transport-Security "max-age=31536000" always;
  add_header X-Content-Type-Options nosniff always;
  add_header X-Frame-Options DENY always;
  add_header Content-Security-Policy "default-src 'self'; style-src 'self' 'unsafe-inline'" always;
  add_header Referrer-Policy no-referrer always;

  # Second layer of rate limiting, in front of the application's own.
  limit_req zone=lookup burst=20 nodelay;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 30s;
  }
}
server { listen 80; server_name water.example.org; return 301 https://$host$request_uri; }
```

```nginx
# in http {}
limit_req_zone $binary_remote_addr zone=lookup:10m rate=20r/m;
```

Set `TRUST_PROXY=true` **only** once nginx is in front. Before that, a client can
spoof `X-Forwarded-For` and bypass rate limiting entirely.

## Process management

```ini
# /etc/systemd/system/seminole-water.service
[Unit]
Description=Seminole Water
After=network.target

[Service]
Type=simple
User=water
WorkingDirectory=/srv/seminole-water
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5
Environment=PORT=3000
Environment=TRUST_PROXY=true
Environment=RETAIN_INVESTIGATIONS=off
Environment=RATE_MAX_LOOKUPS=20
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/srv/seminole-water/data

[Install]
WantedBy=multi-user.target
```

## Monitoring

`GET /api/health` returns uptime, memory, geocode cache hit rate, lookup count,
and per-family sync status. Alert on:

| Signal | Threshold | Why |
| --- | --- | --- |
| endpoint unreachable | 2 consecutive failures | service down |
| `memory_mb` | > 1000 | leak; measured steady-state is ~140 MB |
| `geocode_cache.hit_rate` | < 0.4 after warm-up | upstream geocoder load |
| `local_synced.*` | not `synced` | data went stale or a sync broke |
| HTTP 5xx rate | > 1% over 5 min | application errors |
| p95 latency | > 3 s | upstream geocoder degraded |

```bash
*/5 * * * * curl -fsS --max-time 10 https://water.example.org/api/health >/dev/null || echo "water service down" | mail -s ALERT ops@example.org
```

Measured under load (600 requests, 50 concurrent): p50 70 ms, memory flat at
~140 MB, zero 5xx, rate limiter returning 429 correctly.

## Backups

The application is stateless apart from `data/`. Only two things there cannot
be regenerated by re-running the sync jobs:

- `data/impact.json` — visitor counters
- `data/investigations/` — only if retention is deliberately enabled

Everything else is a cache. Back up nightly, keep 30 days:

```bash
0 3 * * * tar czf /backup/water-$(date +\%F).tgz -C /srv/seminole-water data/impact.json data/systems.json data/pfas/benchmarks.json && find /backup -name 'water-*.tgz' -mtime +30 -delete
```

Recovery is: restore those files, then `npm run sync:all` to rebuild caches.

## Scheduled jobs

```cron
0 3 * * 1  cd /srv/seminole-water && npm run sync:local
0 4 1 * *  cd /srv/seminole-water && npm run sync:epa && systemctl reload seminole-water
0 2 * * *  cd /srv/seminole-water && npm run prune:investigations
```

## Privacy

Submitted addresses are not written to disk by default
(`RETAIN_INVESTIGATIONS=off`). If you enable retention, you are storing home
addresses and a retention notice belongs in your privacy policy. Configure the
proxy not to log request bodies.
